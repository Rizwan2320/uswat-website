## Review fixes, 2026-11-12 (PR #16, main agent's review)
- **R1:** `classifyPath` now returns `forbidden` for any path that is not plain (encoded `%`, `..` or `.` segments, `//`, backslash, control characters). The closed endpoints (send-otp, verify-otp, sign-up, verify-backup-code, generate-backup-codes) are matched case-insensitively; allow-list entries stay exact-case, so a differently cased public path falls to `portal` (needs a session and a second factor) instead of being widened. Tests: every closed endpoint in nine spellings (plain, trailing slash, upper, mixed case, `%2D`, `%2F`, mixed-case base, `/./`, `//`), a handler-level test that none reaches the library, and the case rule for allow-lists. Mutation checks, all caught: non-plain path classed `portal`; closed set matched case-sensitively; allow-list matched case-insensitively; dot segments allowed; `%` allowed. Whether the library's own router decodes or lowercases paths was **not tested**; the gate does not depend on it.
- **R2 (answer: yes, it did write them):** with `amount: 10`, `/two-factor/enable` returned ten backup codes in its response and stored them encrypted (362 characters of ciphertext). The codes were reversible and their endpoints are closed, so users would have been shown codes that do not work. Now `backupCodeOptions.amount` is 0: the response holds an empty list and the stored value decrypts to `[]` (integration test, using the library's own `symmetricDecrypt`). Mutation check: setting the amount back to 10 fails four integration tests.
