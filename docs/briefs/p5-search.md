# Brief: search results page, agent 4, 2026-11-18

- **Objective.** `/search` lists published News, Notices, Events, Jobs, Tenders and Pages that match a word, each linking to its real public address. FR-09 and the plan's P5 line "search ... excluding drafts".
- **What was wrong.** The stock search box was a client component that pushed `/search` on mount, so opening `/search?q=word` cleared the word at once; hits for News linked to `/posts/{slug}`, not `/news/{slug}`; the results used the blog card layout.
- **Paths touched.** `apps/web/src/site/search/*` (new), `app/(site)/(cms)/search/page.tsx` (rewritten), `src/search/Component.tsx` (removed: the buggy box, unused after this), tests, docs. Three in, two out: it removes the client box and the blog-card result layout; no dependency added.
- **How.** A plain GET form (works without JavaScript, results can be linked). `searchSite` reads the `search` collection with no user, so only the published records the plugin synced are visible; match is a case-insensitive "contains" on title, description and slug; 20 per page with the kit pagination. A results page is `noindex, follow`; the empty form page is indexable.
- **Risks.** (1) "Contains" matching, not the full-text and `pg_trgm` search the plan names: that needs a migration and is a P3 decision; ranking is by title only. (2) Departments, programmes and offices are not searchable: `SEARCH_COLLECTIONS` in `plugins/index.ts` leaves them out ("until P5 decides") and adding them needs a re-index. I did not change it. (3) Interface words ("Search", "result(s)", the empty-state sentence) stay English until Urdu is supplied (ADR 0008).
- **Not here.** Highlighting, filters by type, the header search overlay (`SearchOverlay`, not changed; check that it links to `/search?q=`).
- **Tests.** Unit: address mapping, query parsing, hit building. Integration: published notice and news found with the right addresses, draft never returned, empty query and unknown word return nothing, a percent sign is text. Browser: `/search`, a query with 11 hits and one with none at 1440, 1024 and 390 px, both directions; axe at 1440 and 390 px.
